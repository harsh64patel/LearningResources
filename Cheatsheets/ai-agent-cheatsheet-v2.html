End-to-End Agent Development Workflow

From idea to production-grade enterprise agent — the complete journey

Concept ›
flowchart LR A["1️⃣ Define\nGoal"] --> B["2️⃣ Select\nPattern"] B --> C["3️⃣ Set Up\nEnv"] C --> D["4️⃣ Build\nTools"] D --> E["5️⃣ Prompt\nEngineer"] E --> F["6️⃣ Unit\nTest"] F --> G["7️⃣ Integration\nTest"] G --> H["8️⃣ Eval\nHarness"] H --> I["9️⃣ Add\nObserv."] I --> J["🔟 Deploy"] J --> K["↩️ Monitor\n& Iterate"] K --> B style A fill:#3b82f6,color:#fff,stroke:none style J fill:#10b981,color:#fff,stroke:none style K fill:#f59e0b,color:#fff,stroke:none

Detailed Phase Breakdown

1
Define Agent Goal & Scope
What task? What constraints? Single-turn or multi-turn? Autonomous or supervised? Write a 1-paragraph agent spec before any code.
Output: Agent Spec Doc Time: 30 min
2
Select Architecture Pattern
Simple task → ReAct. Complex multi-step → Plan & Execute. Multiple domains → Supervisor+Subagent. Needs docs → RAG+Agent. Real-time UX → Streaming.
Output: Architecture Diagram
3
Set Up Environment
Install framework, set API keys, configure secrets manager, set up logging from day 1. Never hardcode keys.
pip install langchain langchain-openai langgraph langsmith
export OPENAI_API_KEY="sk-..."
export LANGCHAIN_TRACING_V2="true"
export LANGCHAIN_API_KEY="ls__..."
export LANGCHAIN_PROJECT="my-agent"
4
Build & Test Tools Individually
Each tool should be a pure function with typed inputs/outputs. Test each tool in isolation before wiring to agent. Tools are the #1 source of agent bugs.
from langchain.tools import tool
from pydantic import BaseModel

class SearchInput(BaseModel):
    query: str
    max_results: int = 5

@tool(args_schema=SearchInput)
def web_search(query: str, max_results: int = 5) -> str:
    """Search the web for current information."""
    # Your implementation here
    return f"Results for: {query}"

# Test tool BEFORE connecting to agent
print(web_search.invoke({"query": "Python async", "max_results": 3}))
5
Prompt Engineering & System Prompt
Write a clear system prompt. Include: role, capabilities, limitations, output format, and tool usage guidance. Iterate using prompt versioning.
6
Unit Testing
Mock LLM calls using recorded responses. Test each tool function. Test prompt templates. Fast, cheap, deterministic.
7
Integration Testing + Evaluation
Run full agent on test dataset. Use LangSmith / Phoenix for traces. Measure accuracy, latency, cost-per-run, tool call rate. Set pass thresholds.
8
Add Observability
Every production agent needs tracing, token counting, cost tracking, and error alerting from day 1. Not an afterthought.
9
Deploy + Monitor + Iterate
Deploy with feature flags. A/B test prompts. Monitor failure modes. Collect user feedback. Agents improve through iteration, not perfection upfront.
💡 Beginner Tip: Start with a single-tool ReAct agent on a simple task. Get it working end-to-end first, including logging. Then add complexity. Premature multi-agent architecture is the #1 beginner mistake.

What is an AI Agent?

Foundation concepts every developer must know

Concept ›

✅ An Agent IS:

  • • An LLM that decides what actions to take
  • • Can use tools to interact with the world
  • • Runs in a loop until task is done
  • • Has access to memory across steps
  • • Can plan, reason, and adapt

❌ An Agent is NOT:

  • • Just a chatbot (no action loop)
  • • A fixed pipeline (no dynamic decisions)
  • • Magic — it still needs good prompts
  • • Always right — needs error handling
  • • Free — tokens cost money at scale

Pattern #1 — ReAct (Reason + Act)

The foundational agent loop: Think → Act → Observe → Repeat

Beginner Pattern ›
sequenceDiagram participant U as 👤 User participant A as 🧠 Agent LLM participant T as 🔧 Tool U->>A: "What's the weather in Tokyo?" Note over A: Thought: I need the\nweather_search tool A->>T: weather_search("Tokyo") T-->>A: {"temp": "22°C", "cond": "Sunny"} Note over A: Thought: I have the data,\ncan now respond A-->>U: "Tokyo is 22°C and sunny ☀️"

ReAct Prompt Template

REACT_SYSTEM_PROMPT = """You are a helpful AI agent. Always follow this format:

Thought: Think about what you need to do next
Action: tool_name
Action Input: {{"key": "value"}}
Observation: (result from tool - auto-filled)
... (repeat Thought/Action/Observation as needed)
Thought: I now have enough information to answer
Final Answer: Your complete response to the user

Available tools:
{tools_description}

Important: ALWAYS use Thought before Action. NEVER skip steps."""

LangChain Implementation

from langchain.agents import AgentExecutor, create_react_agent
from langchain_openai import ChatOpenAI
from langchain.tools import tool
from langchain import hub

@tool
def web_search(query: str) -> str:
    """Search the web for current information."""
    return f"Search results for: {query}"

@tool
def calculator(expression: str) -> str:
    """Evaluate a mathematical expression safely."""
    import ast
    try:
        return str(ast.literal_eval(expression))
    except:
        return "Error: invalid expression"

tools = [web_search, calculator]
llm = ChatOpenAI(model="gpt-4o", temperature=0)
prompt = hub.pull("hwchase17/react")

agent = create_react_agent(llm, tools, prompt)
agent_executor = AgentExecutor(
    agent=agent,
    tools=tools,
    verbose=True,
    max_iterations=10,
    handle_parsing_errors=True,
    return_intermediate_steps=True,
)

result = agent_executor.invoke({
    "input": "What is 15% of Japan's population?"
})
print(result["output"])

✅ Strengths

  • • Transparent, readable reasoning
  • • Works with any capable LLM
  • • Easy to debug via thought trace
  • • Self-corrects on tool errors

⚠️ Limitations

  • • Can loop infinitely (set max_iterations)
  • • Slow with many tool calls
  • • Context fills up on long tasks
  • • No parallel tool execution

Pattern #3 — Chain of Thought (CoT)

Force step-by-step reasoning before answering

Beginner ›

Standard CoT

prompt = """Solve this step by step:

Problem: {problem}

Think through each step carefully:
Step 1: ...
Step 2: ...
Step 3: ...
Answer: ..."""

Zero-Shot CoT

prompt = """Problem: {problem}

Let's think step by step."""

# The magic phrase "Let's think step by step"
# dramatically improves LLM reasoning quality
# without needing few-shot examples
When to use CoT: Multi-step math, logical reasoning, complex decision trees, code debugging. Not worth it for simple lookups or factual Q&A — adds tokens and latency.

Pattern #4 — Plan & Execute

Separate planning from execution for complex multi-step tasks

Beginner Pattern ›
flowchart TD A["👤 Complex Task"] --> B["🧠 Planner LLM\nBreaks task into steps"] B --> C["📝 Plan:\n1. Search competitors\n2. Analyze prices\n3. Write report"] C --> D["⚙️ Executor: Step 1\nweb_search(competitors)"] D --> E["⚙️ Executor: Step 2\nanalyze_prices(data)"] E --> F["⚙️ Executor: Step 3\nwrite_report(analysis)"] F --> G["🔁 Re-plan if needed"] G --> H["✅ Final Report"] style B fill:#8b5cf6,color:#fff,stroke:none style H fill:#10b981,color:#fff,stroke:none 
from langchain_openai import ChatOpenAI
from langchain.schema import SystemMessage, HumanMessage

llm = ChatOpenAI(model="gpt-4o", temperature=0)

def plan_task(task: str) -> list[str]:
    """Generate a step-by-step plan using a dedicated planning LLM."""
    response = llm.invoke([
        SystemMessage(content="""You are a task planner.
Break the given task into clear, executable steps.
Return ONLY a numbered list. Each step should be actionable."""),
        HumanMessage(content=f"Task: {task}")
    ])
    lines = response.content.strip().split('\n')
    return [l.strip() for l in lines if l.strip()]

def execute_step(step: str, context: dict) -> str:
    """Execute a single plan step using an executor agent."""
    # Route to appropriate tool based on step content
    if "search" in step.lower():
        return web_search(step)
    elif "analyze" in step.lower():
        return analyze_data(context.get("data", ""))
    return f"Executed: {step}"

# Usage
task = "Research top 3 Python web frameworks and write a comparison"
plan = plan_task(task)
context = {}

for i, step in enumerate(plan):
    print(f"Step {i+1}: {step}")
    result = execute_step(step, context)
    context[f"step_{i+1}_result"] = result

Pattern #5 — Human-in-the-Loop (HITL)

Keep humans in the decision loop for high-stakes actions

Beginner Pattern ›
flowchart TD A["Agent proposes action"] --> B{{"Risk Level?"}} B -->|"Low: read-only"| C["Auto-execute"] B -->|"Medium: reversible"| D["Execute + notify"] B -->|"High: irreversible"| E["🛑 Pause & ask human"] E --> F{{"Human Decision"}} F -->|"Approve"| G["Execute with audit log"] F -->|"Reject"| H["Abandon + explain"] F -->|"Modify"| I["Adjust plan + re-propose"] C --> J["Continue"] D --> J G --> J style E fill:#f59e0b,color:#fff,stroke:none style G fill:#10b981,color:#fff,stroke:none 
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.memory import MemorySaver

# LangGraph makes HITL easy via interrupt_before
def build_hitl_agent():
    workflow = StateGraph(AgentState)

    workflow.add_node("agent", call_model)
    workflow.add_node("tools", call_tools)
    workflow.add_node("human_review", human_review_node)

    workflow.set_entry_point("agent")

    # Interrupt BEFORE executing high-risk tools
    workflow.add_conditional_edges("agent", route_agent, {
        "tools": "tools",
        "human_review": "human_review",  # pause here
        END: END,
    })
    workflow.add_edge("tools", "agent")
    workflow.add_edge("human_review", "tools")

    # Memory saver preserves state across interruptions
    memory = MemorySaver()
    return workflow.compile(
        checkpointer=memory,
        interrupt_before=["human_review"]  # pause point
    )

Vector Memory (Semantic)

from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings

# Store memories as embeddings
embeddings = OpenAIEmbeddings()
vectorstore = Chroma(embedding_function=embeddings)

def save_memory(text: str, metadata: dict):
    vectorstore.add_texts([text], metadatas=[metadata])

def recall_memory(query: str, k: int = 3) -> list:
    return vectorstore.similarity_search(query, k=k)

Pattern #6 — Multi-Agent Orchestration

Coordinate multiple specialized agents to solve complex problems

Intermediate Orchestration ›
💡 Core Idea: Instead of one agent doing everything, multiple specialized agents each excel at a sub-domain. An orchestrator coordinates their work. This is the foundation of enterprise agent systems.
flowchart TD U["👤 User: Complex Task"] --> O["🎯 Orchestrator Agent\n(Routes & coordinates)"] O --> A1["🔍 Research Agent\n(Web search, papers)"] O --> A2["💻 Code Agent\n(Write & run code)"] O --> A3["📊 Analysis Agent\n(Data, charts)"] O --> A4["✍️ Writer Agent\n(Reports, summaries)"] A1 --> R["📦 Shared\nResult Store"] A2 --> R A3 --> R A4 --> R R --> O O --> F["✅ Final Synthesized Response"] style O fill:#8b5cf6,color:#fff,stroke:none style F fill:#10b981,color:#fff,stroke:none style R fill:#1e293b,color:#94a3b8,stroke:#2d3748

Orchestration Topologies

⭐
Star / Hub-Spoke
1 orchestrator → N workers. Most common. Easy to reason about. Bottleneck at orchestrator.
➡️
Pipeline / Sequential
A→B→C→D. Each agent passes output to next. Clear data flow. No backtracking.
🔗
Peer / Mesh
Agents communicate directly. Flexible but complex. Emergent behavior possible.

LangGraph Multi-Agent Implementation

from langgraph.graph import StateGraph, END
from langchain_openai import ChatOpenAI
from typing import TypedDict, Annotated
import operator

# Shared state across all agents
class MultiAgentState(TypedDict):
    task: str
    research_result: str
    code_result: str
    analysis_result: str
    final_report: str
    messages: Annotated[list, operator.add]

llm = ChatOpenAI(model="gpt-4o", temperature=0)

# Specialized agents — each with focused system prompt
def research_agent(state: MultiAgentState) -> dict:
    """Handles research and information gathering."""
    response = llm.invoke([
        {"role": "system", "content": "You are an expert researcher. Find relevant information."},
        {"role": "user", "content": f"Research this topic: {state['task']}"}
    ])
    return {"research_result": response.content}

def code_agent(state: MultiAgentState) -> dict:
    """Handles code writing and execution."""
    response = llm.invoke([
        {"role": "system", "content": "You are an expert Python developer. Write clean, tested code."},
        {"role": "user", "content": f"Based on research: {state['research_result']}\nWrite code for: {state['task']}"}
    ])
    return {"code_result": response.content}

def analysis_agent(state: MultiAgentState) -> dict:
    """Handles data analysis and insights."""
    response = llm.invoke([
        {"role": "system", "content": "You are a data analyst. Extract key insights."},
        {"role": "user", "content": f"Analyze: {state['research_result']}"}
    ])
    return {"analysis_result": response.content}

def writer_agent(state: MultiAgentState) -> dict:
    """Synthesizes all results into final report."""
    response = llm.invoke([
        {"role": "system", "content": "You are a technical writer. Create a comprehensive report."},
        {"role": "user", "content": f"""Create final report combining:
Research: {state['research_result']}
Analysis: {state['analysis_result']}
Code: {state['code_result']}"""}
    ])
    return {"final_report": response.content}

# Build the orchestration graph
def build_multi_agent_graph():
    workflow = StateGraph(MultiAgentState)

    workflow.add_node("researcher", research_agent)
    workflow.add_node("coder", code_agent)
    workflow.add_node("analyst", analysis_agent)
    workflow.add_node("writer", writer_agent)

    # Define execution order
    workflow.set_entry_point("researcher")
    workflow.add_edge("researcher", "analyst")
    workflow.add_edge("researcher", "coder")  # parallel
    workflow.add_edge("analyst", "writer")
    workflow.add_edge("coder", "writer")
    workflow.add_edge("writer", END)

    return workflow.compile()

# Run the multi-agent system
graph = build_multi_agent_graph()
result = graph.invoke({
    "task": "Build a Python script to analyze stock prices",
    "research_result": "",
    "code_result": "",
    "analysis_result": "",
    "final_report": "",
    "messages": []
})
print(result["final_report"])

✅ When to Use Multi-Agent

  • • Task requires diverse expertise
  • • Single agent context limit exceeded
  • • Parallel workstreams possible
  • • Quality improves with peer review
  • • Task can be cleanly decomposed

⚠️ Multi-Agent Pitfalls

  • • Much higher token cost
  • • Debugging is exponentially harder
  • • State synchronization is tricky
  • • Latency adds up across agents
  • • Overkill for simple tasks

Pattern #7 — Supervisor + Subagent

A smart orchestrator delegates to specialized worker agents

Intermediate Orchestration ›
💡 Key Difference from Multi-Agent: In Supervisor+Subagent, the supervisor actively decides which agent to call next based on context, and can retry or re-route. It's more dynamic than a static pipeline. The supervisor owns the "plan" while subagents own "execution."
sequenceDiagram participant U as 👤 User participant S as 👔 Supervisor participant R as 🔍 Research Agent participant C as 💻 Code Agent participant Q as ✅ QA Agent U->>S: "Build a data pipeline" Note over S: Analyze task, decide routing S->>R: "Research best Python ETL libraries" R-->>S: "Pandas, DuckDB, Polars recommended" Note over S: Research done → route to coder S->>C: "Write ETL pipeline using Pandas" C-->>S: "Code written [250 lines]" Note over S: Code done → route to QA S->>Q: "Review and test the ETL code" Q-->>S: "Found 2 bugs, here are fixes" Note over S: All steps complete S-->>U: "Pipeline ready ✅ with fixes applied"

LangGraph Supervisor Pattern

from langgraph.graph import StateGraph, END
from langchain_openai import ChatOpenAI
from typing import TypedDict, Literal
import json

llm = ChatOpenAI(model="gpt-4o", temperature=0)

WORKERS = ["researcher", "coder", "qa_agent", "FINISH"]

class SupervisorState(TypedDict):
    task: str
    history: list[dict]
    next_agent: str
    results: dict

SUPERVISOR_PROMPT = """You are a supervisor managing a team of AI agents.

Available agents:
- researcher: Gathers information, searches web, finds facts
- coder: Writes, reviews, and debugs Python code
- qa_agent: Tests code, finds bugs, validates outputs

Based on the task and conversation history, decide which agent to call next.
When the task is complete, respond with FINISH.

Respond ONLY with JSON: {{"next": "agent_name", "instruction": "what to do"}}"""

def supervisor_node(state: SupervisorState) -> dict:
    """Supervisor decides who to call next."""
    messages = [
        {"role": "system", "content": SUPERVISOR_PROMPT},
        {"role": "user", "content": f"Task: {state['task']}\n\nHistory:\n{json.dumps(state['history'], indent=2)}\n\nWho should act next?"}
    ]
    response = llm.invoke(messages)
    decision = json.loads(response.content)
    return {"next_agent": decision["next"], "history": state["history"] + [{"supervisor": decision}]}

def create_worker(name: str, role: str):
    """Factory: create a specialized subagent."""
    def worker(state: SupervisorState) -> dict:
        # Get the last supervisor instruction
        last_instruction = state["history"][-1].get("supervisor", {}).get("instruction", state["task"])
        response = llm.invoke([
            {"role": "system", "content": f"You are a {role}. Complete the given task expertly."},
            {"role": "user", "content": last_instruction}
        ])
        result = {name: response.content}
        return {
            "results": {**state.get("results", {}), **result},
            "history": state["history"] + [{name: response.content[:200] + "..."}]
        }
    return worker

def route(state: SupervisorState) -> str:
    return state["next_agent"]

# Build the graph
workflow = StateGraph(SupervisorState)

workflow.add_node("supervisor", supervisor_node)
workflow.add_node("researcher", create_worker("researcher", "expert researcher"))
workflow.add_node("coder", create_worker("coder", "senior Python developer"))
workflow.add_node("qa_agent", create_worker("qa_agent", "QA engineer"))

workflow.set_entry_point("supervisor")
workflow.add_conditional_edges("supervisor", route, {
    "researcher": "researcher",
    "coder": "coder",

    "FINISH": END,
})
# All workers report back to supervisor
for worker in ["researcher", "coder", "qa_agent"]:

👷 Subagent Design Tips

  • • One job per agent (SRP)
  • • Focused, narrow system prompts
  • • Return structured outputs
  • • Stateless when possible

⚠️ Supervisor Loop Risk: Set a hard limit on supervisor iterations (e.g., max_rounds=20). Without it, a confused supervisor can send agents in circles, burning tokens. Always add a fallback "FINISH after N rounds" rule.

Pattern #8 — Parallel Agent Execution

Run multiple agents or tools simultaneously to slash latency

Intermediate Pattern ›
💡 Why it matters: If 3 agents each take 10s and run sequentially, you wait 30s. Running them in parallel = 10s total. For enterprise agents, parallelism is how you meet SLA requirements.

Method 1: asyncio.gather (Native Python)

import asyncio
from langchain_openai import ChatOpenAI
from langchain.schema import SystemMessage, HumanMessage

llm = ChatOpenAI(model="gpt-4o", temperature=0)

async def research_agent(query: str) -> str:
    """Async research agent."""
    response = await llm.ainvoke([
        SystemMessage(content="You are a researcher. Be concise."),
        HumanMessage(content=query)
    ])
    return response.content

async def code_agent(spec: str) -> str:
    """Async code writing agent."""
    response = await llm.ainvoke([
        SystemMessage(content="You are a Python developer. Write clean code."),
        HumanMessage(content=spec)
    ])
    return response.content

async def analysis_agent(data: str) -> str:
    """Async data analysis agent."""
    response = await llm.ainvoke([
        SystemMessage(content="You are a data analyst. Extract key insights."),
        HumanMessage(content=data)
    ])
    return response.content

async def run_parallel_agents(task: str):
    """Run all agents in parallel using asyncio.gather."""
    print(f"Running 3 agents in parallel for: {task}")

    # All 3 start at the same time
    results = await asyncio.gather(
        research_agent(f"Research: {task}"),
        code_agent(f"Write code for: {task}"),
        analysis_agent(f"Analyze requirements: {task}"),
        return_exceptions=True  # Don't fail all if one fails
    )

    research_result, code_result, analysis_result = results

    # Handle potential exceptions
    for i, r in enumerate(results):
        if isinstance(r, Exception):
            print(f"Agent {i} failed: {r}")

    return {
        "research": research_result,
        "code": code_result,
        "analysis": analysis_result
    }

# Run it
results = asyncio.run(run_parallel_agents("stock price prediction system"))

Method 3: LangGraph Parallel Branches

from langgraph.graph import StateGraph, END
from typing import TypedDict, Annotated
import operator

class ParallelState(TypedDict):
    task: str
    # Annotated with operator.add allows parallel writes
    results: Annotated[list, operator.add]

def agent_a(state): return {"results": [f"Agent A result: {state['task'][:20]}"]}
def agent_b(state): return {"results": [f"Agent B result: {state['task'][:20]}"]}
def agent_c(state): return {"results": [f"Agent C result: {state['task'][:20]}"]}

def merge_results(state):
    combined = "\n".join(state["results"])
    return {"results": [f"MERGED: {combined}"]}

# LangGraph fans out then joins
workflow = StateGraph(ParallelState)
workflow.add_node("fan_out", lambda s: s)  # Entry point
workflow.add_node("agent_a", agent_a)
workflow.add_node("agent_b", agent_b)
workflow.add_node("agent_c", agent_c)
workflow.add_node("merge", merge_results)

workflow.set_entry_point("fan_out")
# Fan out to all 3 agents simultaneously
workflow.add_edge("fan_out", "agent_a")
workflow.add_edge("fan_out", "agent_b")
workflow.add_edge("fan_out", "agent_c")
# Fan in - all must complete before merge
workflow.add_edge("agent_a", "merge")
workflow.add_edge("agent_b", "merge")
workflow.add_edge("agent_c", "merge")
workflow.add_edge("merge", END)

app = workflow.compile()
result = app.invoke({"task": "Analyze this dataset", "results": []})

# 3. Corrective RAG: Validate retrieved docs before using them
def corrective_rag(query: str, retriever, threshold: float = 0.7):
    """Grade retrieved docs and re-search if needed."""
    docs = retriever.get_relevant_documents(query)

    grading_prompt = f"""Rate relevance of this document to the query.
Query: {query}
Document: {{doc}}
Return ONLY a score 0.0-1.0"""

    relevant_docs = []
    for doc in docs:
        score_response = llm.invoke(grading_prompt.format(doc=doc.page_content[:500]))
        try:
            score = float(score_response.content.strip())
            if score >= threshold:
                relevant_docs.append(doc)
        except ValueError:
            relevant_docs.append(doc)

    if not relevant_docs:
        # Fall back to web search
        return web_search_fallback(query)
    return relevant_docs

Method 1: OpenAI Streaming

from openai import OpenAI

client = OpenAI()

# Synchronous streaming
def stream_response(prompt: str):
    """Stream tokens as they're generated."""
    stream = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        stream=True,  # ← This enables streaming
        stream_options={"include_usage": True}  # Get token counts at end
    )

    full_response = ""
    for chunk in stream:
        if chunk.choices and chunk.choices[0].delta.content:
            token = chunk.choices[0].delta.content
            print(token, end="", flush=True)  # Print token immediately
            full_response += token

        # Final chunk contains usage stats
        if chunk.usage:
            print(f"\n\nTokens: {chunk.usage.total_tokens}")

    return full_response

# Usage

Common Pitfalls & How to Avoid Them

Lessons learned from production agent deployments

Pitfalls ›

🔁 Infinite Loops

Agent keeps calling tools without progress.

✅ Fix: Set max_iterations=10, add loop detection, monitor repeated tool calls.

💰 Token Cost Explosion

Long context + many iterations = huge bills.

✅ Fix: Set token budgets, use cheaper models for sub-tasks, truncate history.

🎭 Prompt Injection

Malicious content in tool outputs hijacks agent.

✅ Fix: Sanitize tool outputs, use a guard LLM, never trust external content blindly.

📦 Context Overflow

Tool results + history exceed context window.

✅ Fix: Summarize old history, truncate tool outputs, use sliding window memory.

🔧 Tool Hallucination

Agent calls tools that don't exist or with wrong args.

✅ Fix: Use Pydantic schemas, handle tool errors gracefully, test tools first.

🎯 Premature Multi-Agent

Over-engineering simple tasks with complex systems.

✅ Fix: Start with single agent. Only add complexity when you hit clear limits.

Agent Security & Safety

Protecting enterprise agents from prompt injection, data leaks, and misuse

Security Intermediate ›

🛡️ Security Checklist

  • ☐ Sandbox tool execution — never run agent code with root privileges
  • ☐ Sanitize tool inputs/outputs — prevent prompt injection via external data
  • ☐ Rate limit per user — prevent abuse and runaway costs
  • ☐ Allowlist tool actions — agent can only call approved tools
  • ☐ Log all tool calls — full audit trail for compliance
  • ☐ Use secrets manager — never hardcode API keys
  • ☐ HITL for destructive actions — delete, send, pay require human OK
  • ☐ Output filtering — scan agent responses before sending to users

💉 Prompt Injection Defense

def sanitize_tool_output(output: str) -> str:
    """Strip prompt injection attempts from tool outputs."""
    # Patterns that indicate injection attempts
    injection_patterns = [
        "ignore previous instructions",
        "forget your system prompt",
        "you are now",
        "new instructions:",
        "SYSTEM:",
        "###OVERRIDE###",
    ]
    output_lower = output.lower()
    for pattern in injection_patterns:
        if pattern in output_lower:
            return "[FILTERED: Potentially malicious content removed]"
    # Truncate overly long outputs
    return output[:2000] if len(output) > 2000 else output
